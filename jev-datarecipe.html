Jev Training-Recipe 的当前研究思路

一句话问题

如何通过数据配比，更好地训练 Jev？ 本项目定位为一篇 Training-Recipe 论文，核心贡献放在训练数据算法：研究不同数据组如何组织、如何分配训练比例，以及配比是否需要随训练阶段变化，形成有效的 Jev 训练方案。

研究参考团队此前发表于 ICML 2026 的 Group-wise Data Ordering: Enhancing Instruction Tuning of Large Language Models via Embedding Proximity。同时从现有 Jev 模型论文的数据部分出发，梳理其数据来源、构造方式、监督形式与训练组织，寻找值得改进的具体问题。

与已有 ICML 工作怎样衔接

EP-Order 利用样本表示进行分组和排序，并在组切换处混合相邻组的数据。它提供了从数据结构出发改进训练过程的研究基础。论文正式页面

本项目以 Jev 的数据配比为核心，首先研究各类数据应该获得多少训练曝光，再考虑比例是否随阶段调整、是否与顺序联合设计。配比决定“学多少”，排序决定“先学什么”；实验中可以分别固定其中一个来研究另一个。EP-Order 应作为共同必读的前期工作和顺序对照，而不只是后续补充阅读。

可延续的研究路径是：分析 Jev 训练数据与训练行为，找到现有 recipe 的具体不足，提出对应的数据组织或分配算法，再在相同预算下验证收益。具体不足可能是某类数据投入过多、重要能力覆盖不足、组间训练互相干扰，或者不同阶段需要不同的数据；这些都需要通过数据分析和实验判断。

Jev 训练中我们要研究什么

这里的 Jev 风格模型接收状态、问题与候选项，返回受候选集合约束的概率或决策。开源实现可以使用语言模型 logits、专用 head 或候选编码器。LLM-as-Jev、Releasing the Inner Jev

对数据算法而言，值得关注的是训练池的异构性：不同来源、任务能力、难度、监督形式和字段数量都可能影响数据价值。我们先了解这些差异如何影响训练，再决定配比依据。跨来源泛化、校准与稳健性是评估训练效果的重要维度，其中哪一项成为主要机制，需要后续证据支持。

从现有模型论文的数据部分出发

Intern-Decision 与 SII-Decision 作为目前整理的两篇代表性起点。

论文 原文可确认的数据工作 对我们的启发与边界
Intern-Decision，§4、Appendix B 混合合成文本、公开任务分布、合成视觉交互数据；17,880 个样本对应 23,500 个决策，其中 5,500 个样本带图像；多个字段共享完整 JSON 决策骨架 研究分组时应同时保留来源、任务、字段与样本信息。样本数不能直接当决策数；公开来源也不等于标签全部来自人工。论文没有据此证明某种混合比例最优
SII-Decision / General Decision Models，§6.2、Appendix F.4 两条自身推理链的末端候选分布形成软目标，再训练不思考时的首 token 读出；按能力组织问题并研究数据量，27B 最终使用 39,279 题 作者报告模板合成的收益没有迁移到真实问题，以及容易的自产题缺少训练信号。但 48,358 题实验约半个 epoch 即到时间上限，并且扩展组改变了来源混合，因此不能据此推出普遍的数据饱和结论

这两篇作为代表性起点。读完应能区分：数据从哪里来、为什么保留某条样本、怎样生成目标、怎样分配训练曝光，以及最终收益来自哪一步。

数据算法的研究范围

层面 需要研究的问题 当前定位
数据构造与监督 现有论文用哪些来源，怎样转成决策样本，标签或软目标如何获得？ 建立对训练池的理解，为算法选择提供依据
数据分组与选择 按来源、能力、难度还是模型表示分组？哪些样本应保留？ 为配比定义操作对象；是否引入选样算法待判断
数据配比 各组分配多少训练 token 或决策曝光？比例固定还是动态变化？ 核心研究问题与贡献落点
数据顺序与阶段 是否按组排序或分阶段训练？顺序与配比怎样配合？ 参考 EP-Order，结合具体机制决定是否联合研究

目标是形成有明确依据的数据算法，并解释它为什么能更好地训练 Jev。多收集一些数据、手动调一组比例可以作为探索和基线；最终需要提炼出可复用的规则及其适用条件。

当前可以比较的算法思路

这些思路是用于讨论的候选，不是已经确定的模块组合。

  • 基于数据结构的配比与调度。 参考 EP-Order 的分组视角，研究 Jev 中什么样的分组有助于分配训练预算，以及固定配比与分阶段配比的差别。
  • 基于训练反馈的动态配比。 利用各组学习进度、开发集表现或组间收益调整曝光；参考 Skill-It、Aioli、DoGE，比较它们在 Jev 训练中的适用性。

选哪条路线，应由现有 recipe 的实际不足、可获得的数据和计算预算共同决定。

下一步怎样推进

  1. 拆解现有 recipe。 重点读 Jev 模型论文的数据部分，记录来源、规模、分组、配比、标签、训练阶段与已有消融；缺失信息保留为待确认，不从最终成绩倒推配比有效。
  2. 复用团队的数据算法经验。 共同阅读 EP-Order，明确它处理的问题和可借鉴的机制，再对比数据混合方法。
  3. 建立可比较的训练起点。 在确定数据与预算后，固定模型、读出和训练目标，比较原 recipe、简单均衡配比及有依据的候选方法。配比的均衡单位需要说明是样本、决策字段还是输入 token。
  4. 根据现象提出算法。 先看数据组、曝光量和训练阶段怎样影响结果，再决定使用表示结构、学习进度、迁移估计还是其他信号。
  5. 解释收益并检验泛化。 固定顺序比较配比，固定曝光比较顺序；涉及筛选时区分组内选样与组间重配。比较训练效果时计入算法自身的额外成本。

性能可从任务宏平均准确率、NLL、Brier/ECE、最差组表现与计算成本观察；最终主指标和主要实验以选定的研究问题为准。当前处于文献与方案整理阶段，尚未启动以上训练。

文献对候选贡献的约束

数据混合已有 Skill-It、Aioli、DoGE 等方法，因此需要说明 Jev 的具体问题和我们的改进。若同时进行筛选与配比，可借鉴 CGSD 的归因对照。这些工作按路线选择相应对照，不预先把全部方法堆进一个系统。

共同入门 按这个顺序读

共同研究基础 团队的 ICML 数据排序论文

Group-wise Data Ordering: Enhancing Instruction Tuning of Large Language Models via Embedding Proximity（EP-Order，ICML 2026）应在 A、B 各自精读前共同阅读。重点理解分组依据、组间排序、边界混合，以及实验怎样区分数据结构与训练顺序的作用。

共同讨论：哪些思想可以用于 Jev 数据配比？配比决定各组训练曝光，顺序决定曝光发生的先后；如何分别验证，再决定是否联合设计？这是本项目的前期研究基础，不要求直接套用原算法。

A · Jev 数据与训练 recipe

负责的问题：现有 Jev 论文用了什么数据、怎样构造监督、怎样组织训练，哪些环节值得通过数据算法改进？ 共同阅读的 Intern-Decision 与 SII-Decision 是 recipe 拆解的重点。

A 的最终交付是一份现有 Jev recipe 对照：数据来源与规模、分组与配比、标签获取、训练阶段、已有数据消融及缺失证据。给出少量完整样本，并提出最值得研究的配比问题。现阶段不要求先生成大数据集。

B · 数据配比与训练调度

负责的问题：现有数据算法怎样决定每组学多少、什么时候学，哪些机制值得用于 Jev？ 先共同读 EP-Order，再读以下配比方法。

顺序 核心论文 与本项目最相关的内容 阅读交付
B1 Skill-it! A Data-Driven Skills Framework for Understanding and Training Language Models 技能依赖与在线数据采样 区分分组、依赖估计和曝光分配，判断在 Jev 中需要哪些条件
B2 Aioli: A Unified Optimization Framework for Language Model Data Mixing 混合律、在线影响估计与动态配比 说明如何更新权重、与分层采样有何差别、额外成本是什么

B4 DoReMi: Optimizing Data Mixtures Speeds Up Language Model Pretraining 小代理模型上的 group DRO 与混合比例迁移 对比它与依赖驱动、目标驱动配比的差别，提炼可比较的基线

第二轮按发现的问题选读：DeGMatch 研究梯度公共结构与目标选数；CGSD 拆分组内筛选和组间重配；OP-Mix 研究低成本混合搜索；DoGraph 研究模型视角下的数据域。后两篇不是近一周新稿。

B 的最终交付是一张方法对照图：分组依据 → 配比或调度规则 → 计算成本 → 适用条件。结合 A 的数据梳理，提出可以比较的算法路线；不预先锁定稳健迁移，也不把所有方法拼成一个系统。

阅读时最容易混淆的四件事

  1. 训练 Jev 与用 Jev 处理数据。 Jev-LDE 编辑 ICL 演示；冻结 Jev 给 RL 回放打分；两者都很有意思，但不自动等于改善 Jev 自身的训练配比。
  2. 数据数量与数据机制。 数据量、来源覆盖、候选难度、标签来源、模型起点同时变化，无法单独归因于其中一项。
  3. 语义不变与事实反转。 候选换序应保持答案的语义；PACT 的事实编辑则应改变 gold。两者服务不同的研究问题。
  4. 开发收益与独立泛化。 用某个 benchmark 错误反复补题后，再在同一个 benchmark 提升，不能自动说明跨来源迁移；训练短跑或未完 epoch 也不能证明数据扩充无效。

目前最值得形成的合读结论是：围绕“如何通过数据配比更好地训练 Jev”，结合现有模型的数据工作与团队 EP-Order 的经验，明确实际训练问题，再提出并验证数据算法。 不把检索未命中当作无人做过，不把新稿摘要当作已复现结果。
